# CineMatch AI

CineMatch AI is a full-stack movie and TV discovery web application. It provides a cinematic interface for exploring a curated collection of movies and series, searching titles, viewing details and trailers, and saving favorites to a personal watchlist.

## Features

### User interface
- Responsive landing page with project information and feature highlights.
- Sign-up and sign-in screens.
- Home dashboard with a featured title and curated movie/series collections.
- Browse Movies, TV Shows, Series, and Videos.
- Search titles by name, genre, or year.
- Filter the displayed collection by genre.
- Open a title to view its information.
- Watch trailers in an embedded YouTube player.
- Save and remove titles from Favorites / Watchlist.
- Settings, Help, and logout navigation.

### Backend and data
- FastAPI backend.
- SQLite database for user and session records.
- Account registration and login endpoints.
- Passwords are stored as PBKDF2-HMAC-SHA256 hashes with individual random salts; plaintext passwords are not stored.
- Basic health-check endpoint.

> **Current implementation note:** The movie catalogue and displayed recommendations are defined in the frontend source code. The project currently provides curated/static discovery content; an external movie database API or trained AI recommendation model is not configured in this codebase.

## Prerequisites

Install the following before running the project:

- Node.js and npm
- Python 3
- pip (Python package installer)

## Run the project locally

Run the backend and frontend in separate terminals. Keep both terminals open while using the application.

### 1. Start the backend

Open PowerShell or a terminal and move into the backend directory:

```powershell
cd CineMatch-AI/backend
```

Install the Python dependencies:

```powershell
python -m pip install -r requirements.txt
```

Start the FastAPI server:

```powershell
python -m uvicorn main:app --reload --host 127.0.0.1 --port 8000
```

The backend will be available at:

- API base URL: `http://127.0.0.1:8000`
- Health check: `http://127.0.0.1:8000/health`
- Interactive API documentation: `http://127.0.0.1:8000/docs`

### 2. Start the frontend

Open a **second** terminal and move into the project root (the folder containing `package.json`):

```powershell
cd CineMatch-AI
```

Install the frontend dependencies:

```powershell
npm install
```

Start the Vite development server:

```powershell
npm run dev
```

Open the local URL printed by Vite. By default, it is:

```text
http://localhost:5173
```

### 3. Create an account

1. Open the frontend in your browser.
2. Select **Start Exploring** or **Create Account**.
3. Enter your name, email address, and a password of at least six characters.
4. Sign in with the account you created.

## API endpoints

The current backend exposes these endpoints:

| Method | Endpoint | Description |
|---|---|---|
| `GET` | `/health` | Check whether the API is running |
| `POST` | `/auth/signup` | Register a new user |
| `POST` | `/auth/login` | Authenticate an existing user |

### Example sign-up request

```json
{
  "name": "Demo User",
  "email": "demo@example.com",
  "password": "demo123"
}
```

### Example login request

```json
{
  "email": "demo@example.com",
  "password": "demo123"
}
```

Successful authentication returns a session token and basic user information. The frontend stores the returned token and user data in browser local storage.

## Database

The backend uses SQLite. The database file is located at:

```text
backend/cinematch.db
```

The backend initializes the `users` and `sessions` tables when the application starts. Keep this file if you want to retain the local account records. Do not commit a database containing real user information to a public repository.

## Configuration

The frontend currently uses this backend URL in `src/main.jsx`:

```javascript
const API = "http://127.0.0.1:8000";
```

If the backend runs on another host or port, update this value and configure the backend CORS allowed origins in `backend/main.py` to include the frontend's origin.

## Troubleshooting

### Frontend cannot connect to the backend
- Confirm the backend terminal is still running.
- Open `http://127.0.0.1:8000/health` and check for a successful response.
- Confirm the API URL in `src/main.jsx` matches the backend host and port.

### Python package installation fails
- Confirm Python and pip are installed.
- Run the install command from the `backend` directory.
- If using a virtual environment, activate it before installing dependencies.

### Frontend dependencies or Vite command are missing
- Run `npm install` from the folder containing `package.json`.
- Then run `npm run dev`.

### Port is already in use
- Stop the other process using port `8000` (backend) or `5173` (frontend), or configure the application to use another available port.

## Security and production considerations

This project is suitable as a local demo or hackathon project, but it should be hardened before public production deployment. In particular:

- Serve the application over HTTPS.
- Use secure, HttpOnly cookies or another carefully designed token-storage approach.
- Add authentication and authorization checks to protected backend routes.
- Add session expiry, logout/session-revocation handling, and rate limiting.
- Add email verification and password-reset workflows if required.
- Keep secrets and environment-specific configuration outside source code.
- Use a managed database such as PostgreSQL for a multi-user production deployment.
- Avoid exposing or committing real user data or the local SQLite database.
